数据只存在你自己的浏览器里（localStorage），不经过任何服务器。换浏览器、换设备、清缓存都会看不到之前的数据——请经常用下面的「导出备份」存一份 JSON；别人打开这个链接看到的是他自己浏览器里的数据，互不相通。

待确认事项

干活的规矩

格式规范 ＋
  • 只替换带彩色边框的对话、旁白和心声，框里的呻吟也译成中文。
  • 画面上的大号拟声词、环境音一律不动，保留原样。
  • 字样：竖排白字＋黑描边＋外圈彩色边；颜色取样原框，按颜色区分人物。
  • 字体比原文细一档（Noto Sans SC Bold），字号尽量贴近原文，小框里的短句略小。
  • 译文以翻译文档「中文翻译」栏为准，译名按文档规范统一；中文栏仍是日文、或框在文档里缺行时补译并记录。
翻译流程（核查类交付口径） ＋
  1. 用链接下载的最初原版重新识别日文，整合成一份原文文档。
  2. 先对原文文档做完整性和意思检查，再翻译出译文文档。
  3. 译完逐页检查可读性：看得懂、贴合原意、文风精美。
  4. 核查类任务先逐页比对、只交付原文文档，不先在对话框里回答。

铁律：底图与 OCR 源必须用最初下载的无损原图，不用经手压缩过的版本，避免文件逐版变小、画质下降。

本地嵌字步骤 ＋
  1. 拿素材：从聊天附件或网盘取原图包和翻译文档，本机解压；大文件只走已授权的私有读取，不开公开分享绕过。
  2. 对页：按文档页码标题把每页对到图片文件，抽查确认日文原文和图片一致（以页码和内容为准，不只看文件名）。
  3. 识别文字框：颜色分割找出带彩框的对话、旁白、心声，与文档行数和位置核对。
  4. 本地擦字补背景：OpenCV inpaint 或本地 LaMa，不用云端生图模型。
  5. 嵌字：按格式规范排竖排字；封面和手机/屏幕消息如要求翻译，按各自原样式。
  6. 如要求，在最前面加一张同尺寸声明页。
  7. 自查：看缩略图查日文残留、漏框、颜色错误、有没有碰到拟声词；同色多框的页核对台词别放错框。逐页核查清单就在每页详情里。
  8. 输出：保留原画质（原图 PNG 就输出无损 PNG），按顺序命名；打包发送或上传指定网盘文件夹后核对数量和文件名。

页序有疑点时，按剧情、旁白时间线、服装连续性和对话衔接推理，先把疑点页列进「待确认事项」，确认后再调整，不要直接改。

第二本漫画 · 现行口径 ＋
  • 素材：用户上传 1–10 页 PNG（1200×1600），已含中文对话，仅拟声词为日文。
  • 已废弃：填色改色、字体渲染重排（v2、v3 气泡内约束版）——这条路线已彻底叫停，不要再用。
  • 现行：保留原图字形 100%，只加深原字颜色或调对比度，让字看得清。
  • 加深只针对高饱和的文字；人物肤色、衣服等低饱和部分一律排除，不得改动人物颜色。
本地环境清单 ＋
  • manga-ocr（kha-white/manga-ocr-base）：可用；合成图测试 3/3，真实漫画页准确率未验证，不硬吹。
  • OpenCV inpaint：可用，是经典算法，不是 LaMa，不冒充。
  • LaMa（big-lama.pt 本地 TorchScript）：可用，合成测试端到端通过；真实漫画复杂背景上的擦字质量未验证。
  • 字体：Noto Sans SC 可变字体，wght=700 当 Bold 用。
  • 环境位置：~/workspace/manga-lettering-env 隔离 venv（Pillow / cv2 / torch CPU 等都在里面）。
